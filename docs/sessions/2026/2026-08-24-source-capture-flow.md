# Session — Source Capture Flow

**Session ID:** 2026-08-24-04

**Date:** 2026-08-24

**Status:** Crystallized

## Context

Brownfield Source intake establishes non-canonical evidence. The Workbench needs a deliberate path for an owner to reconfirm useful evidence as specification knowledge without generating an automatic reverse-engineered baseline.

## Decision

Source Capture is initiated by the Project Owner from one reviewed Source through **Capture into…**. The owner deliberately chooses a new Product Artifact, section-owned Product Knowledge, Decision, Open Question or existing knowledge to revise. The ordinary destination draft opens with the Source visible as read-only context; it does not pre-fill or save canonical content.

Normal explicit save creates the canonical record or Revision and retains a visible source-provenance link. Discard leaves the Source unchanged and creates no Product Knowledge, Revision or provenance. A later capture from another Source creates a separate ordinary Revision with its own source provenance.

## Boundary

Source Capture is not batch reverse engineering, code import, synchronization or an AI-driven specification generator. External AI summaries remain evidence that the owner must reinterpret and reconfirm.
