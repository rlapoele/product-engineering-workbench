# Project-start Prototype Scope

**Date:** 2026-08-25
**Status:** Crystallized
**Topic:** UX-006 — Project-start prototype validation

## Objective

Build one isolated, high-fidelity Project-start prototype that makes the Greenfield and Brownfield journeys concrete enough to assess visual direction, interaction clarity and established Product Knowledge boundaries.

## State Map

The prototype covers:

1. The empty Project overview and Create Project entry point.
2. Starting Context selection.
3. Basic setup, including optional Greenfield Project-start Notes or the Brownfield post-creation Source preview.
4. Template, preset and section selection.
5. The Greenfield prepared document with the dismissible Begin with what you know panel and an owner-invoked editable first draft.
6. The Brownfield prepared document with Establish context and non-canonical Source Note entry.

## Constraints

The prototype uses representative static data and local interaction state only. It uses the accepted Workbench Interface Foundation and repository frontend stack, but does not add production authentication, persistence, API calls, Project commands or navigation from the production application.

It must demonstrate that the single MVP template is honestly preselected rather than falsely personalized; Project-start Notes do not become canonical content automatically; and Brownfield Sources are available only after Project creation.

## Validation Plan

Review the visual and interaction states in light and dark themes, on narrow, medium and wide layouts, and through keyboard use. Run the repository's static, build and appropriate browser accessibility checks. The owner then reviews the prototype before any resulting product direction is crystallized.
