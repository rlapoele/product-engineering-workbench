# Session — Project Starting Context and Continuous Evolution Direction

**Session ID:** 2026-08-24-01

**Date:** 2026-08-24

**Status:** Crystallized

## Context

The first-slice Project creation journey begins with a new idea and an empty prepared Specification. The Workbench also needs to support work that begins with existing product evidence, and must remain useful as any Project grows beyond its initial authoring moment.

## Decision

Greenfield and brownfield are Project Starting Contexts rather than permanent Project types, lifecycle states or delivery workflows. Greenfield begins with no prior product evidence. Brownfield begins by deliberately bringing existing product evidence into a new Workbench Project as non-canonical source material.

Source material does not silently become Product Knowledge. The Project Owner explicitly reviews and saves any resulting artifacts or section content through ordinary authoring. Brownfield start is distinct from Project Archive import and does not synchronize an external codebase, infer product facts or manage software delivery.

After either start, one Project evolves continuously through ordinary Product Knowledge authoring, revision, impact assessment, validation and later handoff preparation. New requirements, features and UX/UI knowledge are normal Project evolution, not a restart or a new start mode.
