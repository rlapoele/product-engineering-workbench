# Sessions

This directory contains summaries of product discussions.

Sessions represent the project's working memory.

A session typically contains:

- Context
- Key insights
- Decisions reached
- Open questions
- Suggested updates to project knowledge

Session summaries are intentionally concise.

They serve as the bridge between exploratory conversations and stable documentation.

Not every session results in changes to the project's knowledge.

---

## Session Ordering

Each crystallized session should have a Session ID using the format:

```text
YYYY-MM-DD-NN
```

Where:

- `YYYY-MM-DD` is the session date;
- `NN` is the sequence number for that date, starting at `01`.

The Session ID should appear in the session summary and in `docs/sessions/index.md`.

This avoids relying on row order alone when multiple sessions occur on the same day.

Active working notes that have not yet crystallized do not need a Session ID.

When in doubt, prefer updating an existing document rather than creating a new one.
